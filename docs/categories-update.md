# تقرير تحديث التصنيفات والصور والنقاط

## النتيجة

التحديث مبني على Express وSocket.IO ومخزن البنوك الحالي، دون تغيير إطار العمل. بقيت الواجهة العربية وألوانها وخط Tajawal وتدفق المضيف والنتائج. لا توجد عملية commit أو push أو deploy ضمن هذا التحديث، ولم تُستخدم بيانات الإنتاج في الاختبارات.

## الملفات المعدلة

- `server.js`: إعدادات الغرفة وصلاحياتها، تصفية الأسئلة، جولتان × 10، أنظمة النقاط، منع الخروج أثناء المباراة، توجيه favicon الموجود، مزامنة التصنيفات، وتخزين مؤقت للصور والخطوط المحلية.
- `lib/question-store.js`: ترحيل JSONB القديم، حفظ التصنيفات وربط الأسئلة بها، الحذف الآمن، أخذ عينة عشوائية بدون تكرار، ودمج حفظ الصور.
- `lib/admin.js`: حماية رفع الصور بنفس جلسة المطور، وإبلاغ الغرف بتغييرات الكتالوج بعد نجاح الحفظ.
- `public/index.html`: بطاقات الأقسام وإعداد النقاط في Lobby، إدارة التصنيفات واختيارها للأسئلة، رابط favicon وزر الشعار.
- `public/app.js`: البطاقات الديناميكية، مزامنة إعدادات المضيف، قراءة النقاط من السيرفر، حماية العودة للرئيسية، ونصوص الجولتين.
- `public/settings.js`: إنشاء وتعديل وحذف التصنيفات، رفع الصور ومعاينتها، التصنيف المطلوب للسؤال والاستيراد.
- `package.json` و`package-lock.json`: إضافة `sharp` لفحص الصور وفكها وإعادة ترميزها وتصغيرها.
- `README.md`: قواعد المباراة والاختبارات ونظام التخزين المحدث.
- اختبارات `admin` و`bank-postgres` و`multiplayer` و`question-store` و`ui`: تحديث التوقعات وإضافة تحقق للواجهة والصلاحيات.

## الملفات الجديدة

- `lib/category-images.js`: فحص وحفظ وتقديم صور التصنيفات.
- `migrations/002_wamda_category_images.sql`: الجدول الدائم للصور مع صلاحياته.
- `public/categories.css` و`public/categories-admin.css`: تنسيق البطاقات وإدارتها.
- `public/images/categories/islamic.webp`: نسخة عرض مضغوطة من صورة «إسلاميات» التي أرفقها المستخدم، نحو 77 كيلوبايت.
- `public/images/categories/placeholder.svg`: صورة مؤقتة خفيفة للأقسام التي لم تُرفع لها صورة بعد.
- `tests/categories.test.js` و`tests/scoring.test.js`: الحفظ والترحيل والصور وسباق النقاط.
- هذا التقرير.

## التنظيف المحافظ

حُذفت فقط ملفات خطوط وتجارب مهجورة لا توجد لها أي إحالة في HTML أو CSS أو JavaScript أو السيرفر أو الاختبارات:

- `public/fonts/NotoSansArabic-Regular.ttf`
- `public/fonts/NotoSansArabic-Bold.ttf`
- `public/fonts/NotoSansArabic-OFL.txt`
- `public/fonts/NotoKufiArabic-SemiBold.ttf`
- `public/fonts/NotoKufiArabic-OFL.txt`

بقي Tajawal وترخيصه وأوزانه 400/500/700. نُقل أرشيفا الخطوط الأصليان إلى `design-assets/Tajawal.zip` و`design-assets/Noto_Kufi_Arabic.zip` للحفاظ على المصادر خارج ملفات الموقع المقدمة للمتصفح. بقي favicon وصورة إسلاميات الأصلية كما هما. أزيلت سجلات اتصال اللاعبين التشخيصية فقط؛ سجلات فحص قاعدة البيانات بقيت دون أسرار. بقي مفتاح المظهر القديم `firsthit-theme` حفاظًا على تفضيلات المستخدمين.

## قاعدة البيانات والترحيل

البنوك ما زالت في السجل `id = 1` بجدول `public.wamda_banks`. لا جدول أسئلة جديد ولا نقل إلى مخزن مختلف. أضيف داخل JSONB:

```json
{
  "schemaVersion": 2,
  "categories": [{"id": "science", "name": "علوم", "image": "/images/categories/placeholder.svg"}],
  "banks": [{"questions": [{"categoryId": "science"}]}]
}
```

المثال مختصر لعرض الحقول الجديدة فقط. بقية حقول البنوك والأسئلة ومعرفاتها محفوظة.

عند أول تشغيل، تُضاف التصنيفات إسلاميات وعلوم وأحياء ونباتات وتاريخ، ومعها «أسئلة عامة» للأسئلة السابقة التي لا تحمل تصنيفًا. لا يُحذف نص أو خيار أو إجابة أو معرّف سؤال قديم. الترحيل يتم مرة واحدة، بكتابة مشروطة برقم `revision`. لا يعيد تشغيل الخادم إنشاء تصنيفات أو أسئلة حُذفت بعد الترحيل. البنك القديم الذي يحتوي أقل من 20 سؤالًا يبقى محفوظًا، لكن المباراة لن تبدأ حتى تتوفر 20 سؤالًا مختلفًا في الأقسام المحددة.

الجدول الإضافي الوحيد هو `public.wamda_category_images`:

| الحقل | النوع | الغرض |
| --- | --- | --- |
| id | UUID | معرف صورة عشوائي ثابت |
| data | BYTEA | بيانات WebP ثنائية، حدها 512 كيلوبايت |
| created_at | TIMESTAMPTZ | وقت الحفظ |

الملف SQL كامل في [002_wamda_category_images.sql](../migrations/002_wamda_category_images.sql). لا تنشئ شيفرة تشغيل السيرفر أي جداول تلقائيًا.

## تخزين الصور وحمايتها

لا يوجد بالمشروع نظام Supabase Storage أو مفتاح خدمة له؛ الموجود اتصال PostgreSQL فقط. لذلك استُخدم جدول ثنائي صغير للصور داخل PostgreSQL بالاتصال الموجود، دون إعداد أسرار جديدة أو Base64 داخل JSONB. هذا مناسب لصور الأقسام المحدودة العدد والحجم، ويجعلها دائمة على Supabase رغم restart/redeploy في Render.

- الملفات المقبولة: JPEG وPNG وWebP الثابتة، حتى 2 ميجابايت و4 ملايين بكسل.
- يفحص السيرفر نوع الصورة الفعلي، يفكها ويعيد ترميزها إلى WebP، ويزيل metadata، ويقيد العرض إلى 960×720 دون تكبير صورة صغيرة.
- لا تُحفظ الصورة الناتجة إن تجاوزت 512 كيلوبايت.
- الرفع عبر حدث `adminUploadCategoryImage` المحمي بجلسة المطور. الصور تعرض عبر `/category-images/<uuid>.webp` مع `nosniff` وcache ثابت لأنها لا تُستبدل بنفس المعرف.
- صور الأقسام عامة للعرض فقط. أدوار Supabase العامة لا تقرأ الجدول أو تعدله مباشرة؛ الخادم يقدّم الصورة المطلوبة فقط.
- محليًا دون DATABASE_URL تحفظ الملفات في مجلد `category-images` بجانب `BANKS_FILE` (افتراضيًا `data/category-images`). عند استخدام قرص Render يجب أن يكون كلاهما على القرص الدائم.
- في Render دون قاعدة أو مسار قرص دائم يبقى التعديل والرفع معطلين. وإذا كان جدول الصور غير موجود تظهر خطوة SQL المطلوبة بدل ادعاء نجاح الرفع؛ إدارة أسماء التصنيفات والبنوك الحالية تبقى متاحة إذا كان جدول البنوك جاهزًا.
- الصورة التي تُرفع ثم يُلغى حفظ تصنيفها تبقى في المخزن؛ لا نحذف ملفات تلقائيًا خشية أن تكون مشتركة بين تصنيفات أو نسخة محفوظة في جلسة أخرى.

## إدارة الأقسام والأسئلة

افتح القائمة → وضع المطور. قسم التصنيفات يدعم الاسم والصورة والتعديل والحذف. يحدّث الرد الناجح قائمة التصنيفات وقوائم اختيار تصنيف السؤال فورًا، ويحدّث غرف الانتظار المفتوحة.

لا يسمح السيرفر بحذف تصنيف مرتبط بأي سؤال في أي بنك؛ تظهر أعداد الأسئلة ويجب نقلها أولًا. لا يُحذف سؤال ضمنيًا. عند إنشاء/تعديل سؤال يجب تحديد `categoryId` موجود. الاستيراد يقبل التصنيف في كل سؤال، أو التصنيف الاحتياطي المختار من القائمة للأسئلة التي لا تحدده.

الأقسام الخمسة المبدئية بيانات حقيقية قابلة للإدارة، وليست أسماء مكتوبة داخل واجهة البطاقات. صورة إسلاميات موجودة؛ بقية الصور مؤقتة إلى أن يرفع المطور صورها. التصنيفات الجديدة فارغة؛ صنّف الأسئلة القديمة أو أضف أسئلة قبل محاولة اللعب بها.

## المزامنة وصلاحيات الغرفة

- تحتفظ الغرفة بـ`selectedCategoryIds` و`scoringMode` في السيرفر.
- حدث `updateRoomSettings` يقبل التغيير من المضيف الحالي قبل المباراة فقط، ويتحقق من جميع المعرفات وقيمة نظام النقاط.
- تصل قائمة التصنيفات والاختيارات والنظام وعدد الأسئلة المتاحة في `lobbyUpdate` لكل الغرفة.
- البطاقة كلها زر قابل للتحديد وإلغاء التحديد، بعلامة ✓ و`aria-pressed`. غير المضيف يرى الصور معتمة قليلًا مع بقاء الاسم والعلامة واضحين. إرسال حدث مزور منه مرفوض في السيرفر.
- عند البدء تُنسخ 20 أسئلة مختلفة من البنك المفعّل والأقسام المحددة. لا يصل مفتاح الإجابة قبل إجابة اللاعب أو انتهاء السؤال. تعديلات المطور لا تغيّر أسئلة مباراة بدأت بالفعل.

## النقاط والجولات

| النظام | عدد الفائزين الأقصى | نقاط كل فائز صحيح |
| --- | --- | --- |
| أول لاعب | 1 | 1 |
| أول 3 | 3 | 1 |
| أول 5 | 5 | 1 |
| أول 7 | 7 | 1 |

الترتيب هو ترتيب وصول الإجابات الصحيحة إلى السيرفر. عملية التحقق والتسجيل متزامنة دون انتظار قاعدة البيانات، واللاعب له محاولة واحدة فقط. الإجابة الخاطئة لا تحجز مركزًا. ينتهي السؤال عند اكتمال المراكز، أو إجابة كل الموجودين، أو مرور 20 ثانية. تظهر النقاط التراكمية بين الجولتين وبعد الثانية، والمضيف وحده ينتقل.

الشعار يرجع إلى صفحة الاسم خارج المباراة. أثناء السؤال والمراجعة ونتائج الجولة الأولى يعرض نافذة تأكيد قبل تحديث الصفحة واستعادة اللاعب والنقاط. السيرفر يرفض reset/leave/create/join أثناء اللعب لمنع فقد العضوية. نافذة المطور لها زر عودة للرئيسية بنفس الحماية، لأن الـdialog يمنع الضغط على عناصر الصفحة خلفه.

## نتائج الاختبارات وحدودها

نتيجة التحقق الأصلي من تحديث التصنيفات: **32/32** اختبارًا ناجحًا عبر `npm test`، وفحص المتصفح الفعلي ناجح. أُعيد فحص الواجهة بعد تعديل موضع زر الرئيسية في نافذة المطور.

- اختبارات Node تشمل المباراة كاملة 2×10، الأوضاع 1/3/5/7، تسابق الإجابات وتكرارها، الخطأ لا يحجز مركزًا، النقاط بين الجولتين، صلاحيات المضيف، السؤال الأخير والوقت، انتقال المضيف، ومنع إعادة دخول مباراة جارية.
- اختبارات PostgreSQL محلي باستخدام PGlite: ترحيل بنك قديم من 15 سؤالًا دون فقد المحتوى، الحفظ وإعادة فتح قاعدة البيانات، عدم عودة المحذوفات، تغيير التصنيفات، SQL الصلاحيات، تعارض نسختين من المخزن، ورفع/قراءة الصور بعد restart.
- اختبارات الصور: الملفات غير الصالحة، النوع المزيف، الحجم الزائد، رفض SVG، حفظ WebP، وصلاحية جلسة المطور.
- فحص متصفح فعلي بعروض 320 و390 و1440 في الوضعين: شكل البطاقات، التحديد المتعدد، مزامنة Host/Guest، تعطيل اللاعب، إدارة قسم وصورته، تصنيف سؤال وإعادة تصنيفه، منع حذف مرتبط، العرض بالجوال، العودة للرئيسية، Favicon ونتيجة +1 لكل فائز.
- لم يُختبر اتصال Supabase أو Render الإنتاجي ولم يُنفّذ SQL عليهما، ولم تُغيّر أسرار الإنتاج.
- يستعيد refresh/reconnect اللاعب بهوية ثابتة وtoken سري مع نقاطه وإجابته وترتيب الفائزين. تكرار الإجابة بعد العودة لا يضيف نقاطًا. تفاصيل المهلة والاستضافة في `docs/reconnection.md`. الغرف تبقى بالذاكرة؛ شغّل نسخة خدمة واحدة.

## الخطوة اليدوية المطلوبة قبل النشر

1. جدول `wamda_banks` الموجود لديك لا يحتاج إعادة إنشائه.
2. افتح **Supabase → SQL Editor → New query** بدور **postgres**.
3. انسخ **كل** محتوى [migrations/002_wamda_category_images.sql](../migrations/002_wamda_category_images.sql) ونفّذه. لا يحتوي الملف أسرارًا، ويمكن تشغيله مجددًا دون حذف البيانات.
4. بعد رسالة Success يمكنك مراجعة النسخة محليًا ثم الموافقة على رفعها لاحقًا. لم نفترض أن SQL نُفذ في Supabase.
5. لا تحتاج متغيرات جديدة؛ تبقى `DATABASE_URL` و`ADMIN_CODE` في إعدادات Render فقط. البناء `npm ci` والتشغيل `npm start`.
6. بعد نشر النسخة بنفسك، افتح وضع المطور وتحقق من ظهور حالة حفظ الصور في PostgreSQL، وارفع صورة قسم ثم أعد فتح الصفحة. أضف/صنّف 20 سؤالًا مختلفًا على الأقل قبل بدء مباراة بهذه الأقسام.
